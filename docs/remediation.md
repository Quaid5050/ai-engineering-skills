# Audit remediation and evidence limits

The original [A–I audit](audits/2026-11-26/comprehensive-audit.md) and its inventory remain immutable. This implementation retains existing paths, introduces nine capability plugins (twenty skills), and revises workflow/tooling across the original eight plugins. It covers each roadmap area in instructions, references or automation; it does not claim every production/device/provider acceptance experiment has been completed.

Priority and acceptance criteria below map to the audit's R01–R18 recommendations. Evidence details and reproduction commands are in [evaluation](evaluation.md).

## Maintenance milestones

1. Review this implementation and its evidence; resolve actual blockers before merging. The user has not authorized a merge.
2. Configure the stable required CI gate and publish a versioned migration release only through a separately authorized release action.
3. Promote one target stack at a time: runnable sample, known versions, failed-case evidence, independent task artifact and owner.
4. Run provider/device/cloud drills that cannot be established by local models. Keep them visibly pending until executed.
5. Track task success and time/cost before adding further skills. Retire duplicate or unused guidance instead of optimizing for file count.
