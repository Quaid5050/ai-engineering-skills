# Specialized Engineering

Deliver the requested artifact in `$ARGUMENTS`; do not create infrastructure, accounts or unrelated migrations merely because this procedure mentions them.

## 0. Read the project

Reuse `work-context` and `safe-agent-execution` (foundation plugin). Read the current implementation, actual commands, supported versions and constraints. Load only the applicable parts of [the reference](references/implementation.md). Treat unavailable platform execution as unverified.

## 1. Select the actual domain

Read the relevant profile in the reference, the existing product contract and applicable expert requirements. Choose only the domain being built. Do not claim regulatory or safety certification from this skill.

## 2. Name non-negotiable invariants

Turn domain risks into explicit properties: monetary balance and reconciliation, convergence/conflict policy, public API compatibility, capability permissions, numerical error or hardware timing. State what generic application guidance fails to cover.

## 3. Implement and validate at the right boundary

Reuse shared security, data, systems and quality workflows. Add a small domain fixture with realistic failures and an independent oracle. Where specialized hardware, credentials or expert review are required, distinguish implemented guidance from unverified execution.

## 4. Maintain only justified specialization

Add a separate skill/adapter only when repeated tasks need materially different decisions and there is an owner, reference source and fixture budget. Measure incremental success and remove redundant guidance instead of growing the catalogue by names alone.

## Verification and report

Demonstrate the selected domain invariants under its characteristic failures. Compare task outcomes against the generic workflow; retain the specialization only when it adds value.

Report the artifact, decisions, commands/results, revision, environment and remaining uncertainty. Documentation or a local model is not evidence of production or device behavior.

## Rules

- Never guess financial, safety or regulatory acceptance criteria.
- Do not silently broaden scope to every domain in the profile table.
- Record unsupported hardware and unperformed expert validation.
