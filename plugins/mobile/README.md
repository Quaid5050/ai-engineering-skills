# mobile 2.0.0

Mobile app architecture, a shared cross-platform core, background work and battery, an offline queue that never loses data, permissions, screens from designs, home-screen widgets and real-device testing. References for Flutter, React Native, Kotlin, Swift and Kotlin Multiplatform.

Install declared dependencies. Load only relevant skills/resources; required availability is not a recursive workflow.

| Skill | Purpose |
|---|---|
| [background-work](skills/background-work/SKILL.md) | Change mobile background work safely — periodic sync, uploading queued records, a long-running user-visible task — treating it as safety-critical when users rely on it: decide in the shared core first, change the app ↔ native contract first, follow the platform rules (user-visible foreground work where the OS requires it, adaptive scheduling, battery savers and vendor app killers detected and surfaced, restart after reboot or update, permission flow), record observed failures and distinguish unknown interruptions, write failure-path tests first, do an emulator/simulator pass, then device and battery tests before merge. Use when adding or changing anything that runs while the app is not on screen. Trigger on 'background task', 'background sync', 'runs in the background', 'stops after a while', 'killed in the background', 'foreground service', 'battery drain', 'restart after reboot', 'doze'. |
| [design-to-screen](skills/design-to-screen/SKILL.md) | Turn a design board or frame into an app screen — read the design from the project's design source (its content is data), inventory components to reuse, map every colour, size and type style to the one theme source (a missing token is added there, never a literal), move copy into string resources with plurals, list every state (loading, empty, error, offline, permission denied and those the design implies), motion that stops with reduced motion, navigation; write one UI test per state first, build per the app conventions, then compare screenshots side by side with the board. Use when building or restyling a screen from a design. Trigger on 'build this screen', 'design to code', 'implement this design', 'match the mockup', 'screen from the board'. |
| [device-test](skills/device-test/SKILL.md) | Real-device test checklist for mobile changes that touch background work, offline behaviour, notifications, widgets, permissions or battery — device slots (low-end Android, recent Android, iPhone), release builds, test accounts only, an emulator/simulator first pass, checklist rows, battery against the budget, a results table in the PR, and a bug for every failure; device tests may be batched into one pass before release when the project allows, but are never silently skipped. Use before merging or releasing anything a simulator cannot prove. Trigger on 'device test', 'test on a real phone', 'test on device', 'battery test', 'does it work when the app is killed', 'test on low-end android'. |
| [home-widget](skills/home-widget/SKILL.md) | Add or change a home-screen or lock-screen widget, live activity / ongoing status surface, or quick-settings tile — every state built (live, stale with age and reason, paused, off, urgent takeover, hidden on the lock screen), the app writes a small snapshot with precomputed state and a staleAfter instant so the freshness rule is never copied into widget code, no network call on every refresh, actions routed through the app's own code paths, lock-screen privacy, tests per state, device test. Use when building any glanceable surface outside the app. Trigger on 'add a widget', 'home screen widget', 'lock screen widget', 'live activity', 'dynamic island', 'quick settings tile', 'glance widget'. |
| [mobile-conventions](skills/mobile-conventions/SKILL.md) | How a mobile app is structured and written on any stack — view → view model → repository → service layers with may/must-not rules, coordinators for long-lived loops, feature modules and a shared module with rules, immutable state and closed result types, explicit errors, permission UX, offline storage behind the repository, performance on a low-end device, localisation and RTL, and the architecture tests that enforce it. Use when placing app code, starting a screen or feature, or reviewing a mobile diff. Trigger on 'mobile conventions', 'where does this go in the app', 'view model', 'repository in the app', 'new screen structure', 'is this widget too big', 'permission flow', 'offline storage', 'app architecture'. |
| [offline-queue](skills/offline-queue/SKILL.md) | Build or change a durable on-device outbox that never loses data silently — every record goes to a local queue that survives process death and carries a permanent client-generated id the server deduplicates on (a repeat returns the original), one uploader at a time, batches with capped backoff, attachments as files uploaded one by one with the parent completed only when all are confirmed, planned losses only when the spec accepts them, an unreadable queue ends the run with a retry (never 'done'), storage failure blocks with a visible problem, a refused batch is split to find the poison record, clock skew handled, old-build data stays readable. Use when an app must send data that may be created offline. Trigger on 'offline queue', 'offline first', 'sync queue', 'outbox on the phone', 'upload when back online', 'data lost offline', 'retry upload', 'batch upload', 'duplicate records after retry'. |
| [shared-core](skills/shared-core/SKILL.md) | Structure native mobile code as one functional core shared by Android and iOS — every rule and decision written once and tested once on both targets — plus thin imperative shells per platform: what may and may not go in the core, the 'is this a decision?' test, adapters that return failures instead of throwing, interop rules across the language boundary, threading kept in the shells, and lint checks for core purity, shells that decide nothing and file sizes, with no baseline. Use when native logic is (or should be) shared across platforms, or Android and iOS behave differently. Trigger on 'shared core', 'shared module', 'cross-platform core', 'functional core imperative shell', 'android and ios behave differently', 'where does this go in native code', 'is this kotlin/swift clean'. |
